# 贴吧拾光

把贴吧图文和讨论，收进好看的卡片。适用于 AstrBot 4.24.1 及以上版本的 QQ / OneBot v11 环境，支持 NapCat、SnowLuma 等兼容接入端。

## 功能

- 识别帖子链接、吧主页、公开用户主页、QQ JSON/XML 分享卡片，以及通过 QQ 转发的贴吧微信小程序卡片。
- 保留正文图文顺序、真实昵称、头像、接口返回的吧等级、时间、点赞、回复楼层与楼中楼，支持只看楼主和回复排序。
- 提供暖纸书简、夜航星图、清雾山岚、达妮娅泡影、初音舞台、哔哩哔哩六套主题，默认使用 `denia`。
- 优先生成完整长图，超过渲染限额时输出续图；也可选择分页图片或合并转发聊天记录，并附带正文原图和 GIF。
- 默认使用霞鹜文楷，可在控制台上传自定义字体，按全局、分群或单次解析选择。
- 自动识别 AstrBot 已配置的渲染服务和已安装浏览器，也可在控制台自选渲染方式、下载精简或完整 Chromium。
- 支持群黑名单、分群覆盖、私聊开关、会话冷却、重复链接去重、任务队列、内容缓存和自动回收。
- 使用 QQ 贴表情反馈开始、完成和失败状态；具体效果取决于接入端和账号能力。
- 内置中文控制台，支持解析预览、任务进度、历史检索、重新解析、配置管理和 PNG / Markdown / JSON / ZIP 导出。

## 安装

1. 在 AstrBot 插件管理中上传插件 ZIP，或在 AstrBot 项目根目录克隆本仓库：

   ```bash
   git clone https://github.com/yuukana1/astrbot_plugin_tieba_lens.git data/plugins/astrbot_plugin_tieba_lens
   ```
2. AstrBot 会安装 `requirements.txt` 中的依赖。打开控制台的“渲染管理”，已有服务或浏览器会自动识别；没有可用环境时，点击“准备精简 Chromium”即可下载并准备本地渲染，无需填写渲染服务地址。
3. 在 AstrBot 中配置 OneBot v11 接入端，并确认机器人能够发送图片。打开插件配置，按需调整自动解析、主题和评论范围。

安装或更新插件后，在 **AstrBot WebUI → 插件 → 贴吧拾光** 中打开 **贴吧控制台**。不同版本的 WebUI 可能将入口称为“页面”或“视图”。

## 使用

直接将贴吧链接、QQ 分享卡片或可识别的小程序发给机器人，或使用指令：

```text
/贴吧 https://tieba.baidu.com/p/帖子编号
/贴吧 https://tieba.baidu.com/p/帖子编号 --评论 20 --楼中楼 6 --记录
/贴吧 https://tieba.baidu.com/p/帖子编号 --记录 --原图
/贴吧 原神 --帖子 10
/贴吧 https://tieba.baidu.com/f?kw=原神 --主题 雾
/贴吧 https://tieba.baidu.com/p/帖子编号 --只看楼主 --最新
```

| 参数 | 用途 |
| --- | --- |
| `--评论 0~100` | 回复楼层数量，不含首楼；0 表示仅首楼 |
| `--楼中楼 0~20` | 每层楼最多展示的楼中楼数量 |
| `--帖子 1~30` | 主页帖子数量 |
| `--记录`、`--卡片` | 选择合并转发或图片卡片 |
| `--原图` | 在聊天记录中附带正文原始图片 |
| `--只看楼主` | 仅保留楼主发表的内容 |
| `--最新`、`--热门` | 切换回复排序 |
| `--无图` | 不展开正文图片 |
| `--长图`、`--分页` | 选择整张长图或分页模式 |
| `--主题 纸\|夜\|雾\|达妮娅\|初音\|B站` | 本次解析使用的主题 |
| `--字体 文楷\|自定义` | 本次解析使用的字体 |

| 指令 | 用途 |
| --- | --- |
| `/贴吧帮助` | 查看参数与指令说明 |
| `/贴吧状态` | 查看当前群的有效设置与任务数 |
| `/贴吧面板` | 查看控制台入口说明 |
| `/贴吧禁用`、`/贴吧启用` | 管理员停用或恢复当前群 |
| `/贴吧黑名单 添加 群号` | 管理员加入群黑名单 |
| `/贴吧黑名单 删除 群号`、`/贴吧黑名单 列表` | 管理员维护黑名单 |
| `/贴吧清缓存` | 管理员清理内容缓存 |

支持 `tieba.baidu.com/p/…`、`/f?kw=…`、`/home/main?id=…`、旧版移动帖子地址和 `tb.baidu.com` 短链。普通二维码图片不会通过 OCR 自动访问。

贴吧微信小程序卡片中的 `m.q.qq.com` 短链会通过当前 QQ 接入端查询原始页面，再解析帖子。此功能需要 NapCat / SnowLuma 提供 `send_packet` 且发包后端可用；不支持该能力、短链失效或查询超时时会提示改发原帖链接。仅查询当前消息中明确标识为贴吧的卡片，并核对返回的贴吧小程序 ID；普通文本中的 QQ 短链不会自动触发。

## 控制台与字体

控制台通过 AstrBot 的官方页面桥接使用 WebUI 身份认证，无需另设端口或口令。手动解析只生成预览和下载结果；“重新解析”会重新生成结果，不会向 QQ 发送消息。

在 **设置 → 卡片与分页 → 自定义字体** 上传 TTF、OTF、WOFF 或 WOFF2 文件，单个文件最大 32 MB。上传后可应用到全局，也可在分群规则或本次解析中单独选择；恢复默认后使用霞鹜文楷。自定义字体保存在插件数据目录，不会随插件代码更新被覆盖。

默认字体以一份完整 WOFF2 随插件离线提供，保留原有全部字形。渲染时按本次文字生成较小的网页字体子集，降低浏览器和渲染服务的传输、内存开销；首次使用时，会在插件数据目录生成供字体处理和 Pillow 页脚使用的缓存，后续直接复用，损坏时自动重建，无需额外下载字体。

在 **设置 → 渲染管理** 可选择自动、AstrBot 已配置服务或本地浏览器。自动模式优先复用可用服务，再使用已安装浏览器；没有可用环境时，机器人会提示前往控制台准备，不会在聊天处理中自动下载。服务不可用时，自动模式会尝试已有本地环境；手动指定的方式不会擅自切换。

本地渲染推荐精简 Chromium，同样支持卡片的字体、图片和 CSS 效果。每次仅处理一张截图，连续任务复用浏览器，页面用完即释放；空闲 45 秒自动关闭浏览器进程，内核文件保留以供下次启动。浏览器及运行库由面板准备流程自动检查；网络或权限不足时会显示原因并允许重试。完整 Chromium 也可在面板单独下载和选择。

群黑名单始终优先于分群覆盖。控制台保存的配置即时生效，通过 AstrBot 原生插件配置修改时遵循框架的插件重载流程。

“展示来源信息”控制卡片中的原帖链接、读取说明和收录数量提示，支持全局、分群和单次解析。更改只影响新生成的结果，历史图片可通过重新解析更新。完整读取记录保留在任务详情及 JSON / Markdown 导出中。

## 默认设置

- 首楼加 12 条评论，每楼最多 6 条楼中楼；主页 10 条帖子。回复默认按已获取范围内的点赞数降序排列，首楼固定最前。
- 卡片宽 960 px，优先整张长图，最多 12 张；分页模式每页约 3000 px。多图在 QQ 自动合并为聊天记录，正文原图默认不附带。
- 同一会话冷却 5 秒，相同链接去重 120 秒；内容缓存 30 分钟，历史和图片保留 24 小时。
- 每 10 分钟清理一次，解析结果与任务账本的默认缓存预算为 256 MB，最多保留 200 个历史任务；浏览器内核、自定义字体和渲染临时文件不计入此预算。队列最多 16 个任务，默认同时处理 2 个。

## 数据与常见限制

任务记录、内容缓存、图片和自定义字体保存在 `data/plugin_data/astrbot_plugin_tieba_lens/`。插件目录仅保存代码与素材。插件停止时会取消处理中的任务，被中断任务可在下次启动后重新解析。

Cookie 为可选配置，仅在公开接口需要登录时填写自己的贴吧 Cookie。控制台不回显已保存的 Cookie，日志与导出不包含该值。分享插件时不要打包自己的运行数据或 AstrBot 配置。

- 插件只呈现本次接口返回的公开数据。吧等级缺失时不显示等级；删除、权限不足、验证码、超时和空响应会单独提示。
- 用户主页展示公开接口返回的首批动态。仅含旧 `un=` 用户名或无法恢复地址的卡片可能无法读取，可改发原帖链接。
- 未展开的楼中楼、图片或后续页面会按设置显示说明。长文不会按固定字数截断，已取回内容可导出 Markdown / JSON。
- 热度排序只针对已获取的回复，无法保证覆盖源站未返回的楼层；点赞和评论数均为读取时的快照。缺失的源站楼层号会标为展示序号。
- 视频和语音保留可读提示或原链接，插件不自动转发完整视频。
- 收到 HTTP 403 / 429 等验证状态后，会进入 15 分钟请求冷却，可在控制台诊断中查看。
- 读取任务可并行，图像解码、排版和 PNG 编码依次执行，降低高峰内存占用。本地浏览器意外崩溃或卡住时会释放并恢复一次，页面、浏览器和驱动关闭均有独立超时；普通解析错误和尺寸超限仍按各自原因处理。
- 若图片生成失败，可在“渲染管理”重新检测或准备环境。若已生成图片但发送失败，控制台会保留预览和下载结果；明确的媒体上传连接失败最多尝试三次，结果未知的超时不会自动重发。永久上传错误不会盲目重试，零发送时允许处理原因后重发。
- 去重覆盖整个处理过程，并从任务完成时开始计时；重载后保留已发送、部分发送或发送结果未知任务的剩余保护。统计或发送记录写入异常不会将 QQ 已确认成功的发送改成失败。
